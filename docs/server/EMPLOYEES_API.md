# «Мельница»: подключение сотрудников к серверу

## Что реализовано в Android-клиенте

Один владелец организации; карточка сотрудника (обзор, работа, карта, доступ);
права на разделы и запись; отдельные права на прошлые смены и сдачу отчётов;
активен / только просмотр / заблокирован / архив; отзыв всех сеансов; причины
блокировки и журнал изменений. При блокировке данные и открытая смена сохраняются.

В локальном режиме администратор видит только данные, сохранённые на этом телефоне.
Список аккаунтов и маршруты других телефонов появляются после подключения API.
Никаких вымышленных точек, времени соединения и примеров сотрудников не добавлено.

HTTP-клиент, обработка 401/403/409, восстановление данных, очередь с повтором одного
operationId, обновление прав и Android-служба фонового GPS-обмена включены в код.
Сервер в этом архиве НЕ развёрнут. Для существующего Telegram backend нужно
реализовать описанные ниже маршруты или адаптировать EmployeeServerApi к его API.
Добавление одного URL к несовместимому backend недостаточно.

## Включение

Без MELNITSA_API_URL приложение использует существующие локальные аккаунты.
Для серверной сборки:

```sh
flutter build apk --release --dart-define=MELNITSA_API_URL=https://YOUR-SERVER
```

Все пути ниже дописываются как `/v1/...`. URL — HTTPS, без query, fragment и userinfo.
Не включать пароль, токен или Telegram ID владельца в исходники/параметры сборки.

При серверном запуске создание первого локального администратора выключено.
Единственного владельца закрепить в БД по постоянному account ID. Роль admin сама
по себе не даёт права владельца. API должен вычислять isOwner на сервере.
Клиент не отправляет команд назначения второго владельца.

## Сопоставление старых данных

До включения серверной сборки: резервная копия локальных данных и БД mini app;
проверенное соответствие local account ID → server account ID → Telegram ID.
Не сопоставлять по отображаемому имени. Если в старой локальной базе несколько
администраторов и ownerId ещё не задан, клиент останавливает неоднозначную миграцию.

Аккаунтная область данных использует постоянный ID. При смене ID нужна явная
миграция ключей журналов, loader-журнала и Android SQLite GPS account, а не просто
переименование логина. Она зависит от реальной БД и должна выполняться после
проверки сопоставления, не автоматически этим патчем.

Первый серверный вход загружает /me/data. Восстановление имеет промежуточную запись,
поэтому может повториться после сбоя. Если под этим ID уже есть локальные данные,
но нет server version, клиент запрещает молча затереть их и требует миграцию.

## Авторизация и формат employee

Все запросы кроме login: `Authorization: Bearer <accessToken>`.
Токен должен содержать sessionEpoch либо ссылаться на серверную сессию с epoch.
Проверять epoch и статус на КАЖДОМ запросе, включая телеметрию.
Пароль не сохраняется в клиенте. Flutter держит bearer в памяти; Android-служба
хранит свою копию зашифрованной AES-GCM ключом Android Keystore в приватных prefs.
После холодного старта интерфейс требует вход; работающая GPS-служба может продолжать
свою открытую смену с сохранённым токеном до отзыва/истечения допуска.

```json
{
  "id": "stable-server-account-id",
  "name": "Сотрудник",
  "login": "driver01",
  "role": "driver",
  "active": true,
  "isOwner": false,
  "hourlyRateMinor": 0,
  "loaderDeductions": {},
  "access": {
    "status": "active",
    "readable": ["work", "statistics", "salary", "gas", "advance", "maintenance", "invoices", "money", "directions", "settings"],
    "writable": ["work", "gas", "advance", "maintenance", "invoices", "money", "directions"],
    "editHistory": false,
    "submitReports": true,
    "shareLocation": true,
    "reason": "",
    "revision": 1,
    "sessionEpoch": 1,
    "validUntil": "2026-10-12T20:00:00.000Z"
  }
}
```

Пример validUntil не копировать в боевые ответы: выдавать новый UTC-допуск от времени
сервера, рекомендуется до 24 часов. Формат времени для Android — RFC3339 UTC Z с
нулём или тремя дробными цифрами. Неизвестный status — ошибка, а не active.
Статусы: active, readOnly, blocked, archived. Для blocked/archived active=false.
Права записи — подмножество просмотра. Зарплата входит в статистику; клиент закрывает
статистику при отключённой зарплате. Владелец защищён от блокировки/архива/понижения.

## Маршруты API

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| POST /auth/login | login, password | accessToken, employee |
| GET /me | — | employee |
| GET /employees | Только владелец | employees: employee[] |
| POST /employees | name, login, role, active, password, hourlyRateMinor? | employee |
| PATCH /employees/{id} | name, login, role, active; password?; hourlyRateMinor?; deductionMonth?; deductionMinor? | employee |
| PUT /employees/{id}/access | expectedRevision, access, revokeSessions | employee |
| GET /employees/{id}/audit | Только владелец | events[] |
| GET /me/data | Собственные данные | accountId, version, preferences, loaderShifts |
| POST /me/sync | operationId, baseVersion, data | operationId, version |
| GET /me/routes/{shiftId} | Собственная история маршрута | points[], distanceKm? |
| POST /me/routes/{shiftId} | route | accountId, shiftId |
| POST /me/telemetry | shiftId, shift, route | {} |
| GET /employees/{id}/data | Только владелец | accountId, receivedAt, preferences, loaderShifts, liveShift? |
| GET /employees/{id}/routes/{shiftId} | Только владелец | points[] |

`deductionMonth` — YYYY-MM, суммы rate/deduction — целые тиыны. Не передавать
password hash/salt в employee, audit, /me/data или ответы списка.
PATCH профиля не должен обходить отдельное управление доступом: изменение active
запрещать, если оно не совпадает с текущим статусом; менять доступ через /access.
Второй admin запрещён; водитель/грузчик не может назначать роли/права самостоятельно.

### Транзакция управления доступом

1. Проверить владельца по БД, target != ownerId.
2. Сравнить expectedRevision с текущей access.revision. Несовпадение → 409.
3. Валидировать ключи прав, причину, совместимость роли. Игнорировать присланные
   revision/sessionEpoch/validUntil как значения авторитетных серверных полей.
4. Увеличить revision. revokeSessions=true увеличивает sessionEpoch; новые логины
   разрешены при active. Блокировка/архив запрещают рабочие API независимо от epoch.
5. Сохранить состояние и событие audit в одной транзакции. Ответить employee.

Audit: `{at, actorId, action, before?, after}`. action: employee_created,
profile_changed, access_changed, revoke_sessions. Пароли/токены не журналировать.
Серверный журнал append-only; клиентские копии не считаются источником аудита.

### Данные и синхронизация

`preferences` — объект существующих аккаунтных ключей приложения. Его значения
сохраняют исходные типы; journal, gas_reports_v1 и другие документы остаются JSON
СТРОКАМИ, а не вложенными объектами. `loaderShifts` — массив {day, minutes, rateMinor}.
Форматы каждого документа определены в текущих Dart-моделях проекта.

`POST /me/sync`:

```json
{
  "operationId": "48-hex-random-id",
  "baseVersion": 0,
  "data": {
    "accountId": "stable-server-account-id",
    "receivedAt": null,
    "preferences": {},
    "loaderShifts": []
  }
}
```

Сервер доверяет идентичности из bearer, не data.accountId. receivedAt назначает сервер.
Синхронизация сейчас — полный снимок, до 12 MiB; для большой миграции нужен отдельный
пакетный импорт. Клиент не обрезает историю, если лимит превышен, и показывает ошибку.

Одна транзакция: сначала найти уже обработанный (accountId, operationId). Если он
есть, вернуть ПРЕЖНИЙ ответ даже при изменившейся baseVersion. Для нового ID сравнить
baseVersion: несовпадение → 409 без изменения данных. Валидировать изменения относительно
предыдущего снимка и текущих прав: запрет readOnly/blocked, закрытых смен без editHistory,
сдачи без submitReports, настроек без settings, чужих данных, невозможных показаний.
Сервер отдельно авторитетен по ставке, удержаниям, ролям и данным расчётной политики:
их нельзя принимать без проверки из произвольного JSON-журнала.

Затем сохранить данные, поднять version и receipt атомарно. Срок хранения receipt
должен покрывать все возможные повторы очереди; безопасный вариант — сохранять их
постоянно либо вводить согласованный протокол сборки мусора, которого сейчас нет.

Закрытые GPS-маршруты передаются отдельно, по одной смене за цикл через
POST /me/routes/{shiftId}; повтор заменяет проекцию, а не суммирует километры.
Подтверждение содержит accountId и shiftId. Не заменять более свежий трек старым
и не удалять сохранённые точки пустым массивом. Этот endpoint не меняет version
рабочего снимка. GET /me/routes используется сотрудником для истории на новом телефоне.
Таким образом многомесячные маршруты не раздувают каждый рабочий пакет.

Клиент держит только один неизменяемый in-flight пакет на аккаунт. Новые местные записи
остаются в основном журнале и уйдут следующим пакетом после подтверждения первого.
Ответ чужой/прошлой сессии не применяется. Повтор после падения между подтверждением
версии и удалением очереди безопасен благодаря receipt.

При 409 автоматического слияния НЕТ: записи и pending сохраняются, в меню аккаунта
показывается конфликт. До массового многотелефонного использования нужен регламент
сверки владельцем или серверное слияние по предметным ID. Не решать конфликт
посылкой force=true или удалением местной очереди. В обычном режиме — один рабочий
телефон сотрудника. Новое устройство скачивает /me/data; старое отзывается.

### Геоданные в фоне

Служба Android собирает GPS только во время открытой смены и с системным разрешением.
Каждые примерно 30 секунд работающая служба проверяет GET /me; при shareLocation=true
посылает /me/telemetry. HTTP выполняется вне очереди GPS и не тормозит подсчёт расстояния.
Ограничения ОС/отсутствие сети/принудительная остановка могут задержать передачу.
Карта всегда показывает timestamp последней точки; точка старше 120 секунд отмечается
как устаревшая. «Онлайн» по старой точке не рисуется.

Тело telemetry: shiftId, shift (копия локальной смены), route — результат Android
GpsDatabase.route: points, distanceKm и другие метаданные. Поля точки: lat, lng,
accuracy (метры), speed, time (UTC), breakBefore. GPS route визуально прорежен примерно
до 4000 точек; distanceKm берётся из отдельного полного счётчика, не из длины полилинии.
Для точного полного сырого трека нужен отдельный экспорт SQLite, не эта карта.

Сервер проверяет доступ/epoch/shareLocation/владельца смены. Телеметрия хранится отдельно
от финансового журнала и НЕ поднимает version рабочего снимка. Повтор одинакового
маршрута заменяет его проекцию или идемпотентно объединяет точки; пробег не суммировать
повторно. Старый полный снимок не должен стирать более свежую телеметрию.

Если журнал новой смены ещё не пришёл, сервер может вернуть её проверенную копию
как liveShift в /employees/{id}/data; UI покажет смену и маршрут. Эта проекция не должна
перезаписывать закрытую смену или считаться подтверждением зарплаты. Финальный рабочий
снимок и closure имеют приоритет над запоздалой телеметрией. Если shift уже закрыта,
повторная telemetry не открывает её заново.

При получении блокировки/отзыва служба останавливается, локальный маршрут и счётчики
сохраняются. Просроченный validUntil также останавливает запись, даже без сети.
Приложение показывает экран блокировки/проверки. Нативная служба не может обеспечить
мгновенный удалённый запрет без сети; сервер сразу запрещает обращения со старым доступом.

## Приёмка перед включением реальных сотрудников

- flutter analyze; flutter test test/employee_access_test.dart; собрать APK.
- Два Android: владелец + водитель. Создать сотрудника, войти, смена/рейс/газ.
- Сверить цифры, затем свернуть/убрать приложение: маршрут обновляется, время точки видно.
- Отключить сеть: данные сохраняются; после сети нет дублей.
- Заблокировать открытый экран и фоновую смену: ввод закрывается, GPS останавливается,
  сохранённая смена остаётся незавершённой. Восстановить доступ и войти заново.
- Отозвать сеансы; старый bearer не работает, новый логин разрешён.
- readOnly запрещает записи через UI И прямой HTTP.
- Права и смены разных сотрудников не смешиваются при быстром выходе/входе.
- Подменённые accountId, isOwner, salaryRate, unknown permissions отвергаются сервером.
- Повтор operationId и перезапуск после подтверждения не создают второй расход/рейс.
- 409 оставляет местный снимок; 401/403 не переводит приложение в локальный режим.
- Архив не удаляет историю. Просроченная lease блокирует без интернета.

Эта инструкция описывает клиентский контракт. Реальный сервер, миграцию Telegram ID,
боевую интеграцию и тесты на двух устройствах нельзя считать выполненными до подключения.
